# Pi and Langfuse compatibility — 2026-11-26

Extension 0.1.3 locks Pi 0.79.8 and Langfuse tracing/otel 5.3.0. The current releases are [Pi 1.6.1](https://registry.npmjs.org/@earendil-works/pi-coding-agent/1.6.1), [Langfuse tracing](https://registry.npmjs.org/@langfuse/tracing/6.1.1) and [otel](https://registry.npmjs.org/@langfuse/otel/6.1.1) 6.1.1, and [Langfuse server 4.86.0](https://github.com/langfuse/langfuse/releases/tag/v4.86.0). Pi 1.6.1 requires Node 22.19.0+, more specific than the README's 22+.

1. **Repair Cloud verification first.** The [Cloud API notice](https://langfuse.com/llms.txt) dates removal of legacy trace and observation reads to November 16. Both `tests/e2e-langfuse.test.ts` and the testing skill still use them. Poll `/api/public/v2/observations` for the unique test session, request the fields used in assertions, and wait for the expected parent/child set rather than the first span. See the [endpoint mapping](https://langfuse.com/faq/all/deprecated-api-migration). This concerns read-back, not production export: `src/transport.ts` already uses the OTel processor. `/langfuse-test` checks project access, not trace delivery.
2. **Choose the self-hosted support floor before updating the SDK.** [Langfuse v6](https://langfuse.com/docs/observability/sdk/upgrade-path/js-v5-to-v6) requires Cloud or server 4.59.0+. Stay on v5 if supporting older installations. For v6, change the manual `langfuse.trace.metadata.*` writer in `src/transport.ts` to match SDK JSON encoding and its 200-character *encoded* limit. Test decoded strings, including quotes, on both root and child spans. Don't just loosen the observation assertion.
3. **Add a current-Pi compatibility job and preserve retry visibility.** Pi is a wildcard peer, but CI installs the lockfile. [Pi 1.6.1](https://github.com/earendil-works/pi/blob/v1.6.1/packages/coding-agent/CHANGELOG.md) emits `after_provider_response` for error and retried attempts on more providers. `index.ts` replaces the previous response for the active generation. Test two responses (429 then 200) to one request: retain the final success and a count of prior failures without double-counting tokens or exporting more raw headers.
4. **Prioritize metadata over broader content capture.** [Pi's usage contract](https://github.com/earendil-works/pi/blob/v1.6.1/packages/ai/src/types.ts) reports optional reasoning tokens (already included in output) and `cost.totalFromProvider`. `src/telemetry.ts` drops both. Expose billed versus estimated cost and split reasoning without inflating totals. Langfuse now [maintains its own experimental Pi plugin](https://langfuse.com/integrations/developer-tools/pi-agent) with time to first token, nested subagents, and image uploads. Document the choice: keep this extension metadata-only by default; consider first-token latency before adding media or prompt capture. Use one exporter per run to avoid duplicate traces.

**Compatibility probe:** in a disposable copy on Node 26.13.1, installed Pi 1.6.1 and both Langfuse packages at 6.1.1 against unchanged extension source. `npm run typecheck` passed. `npm test`: 76 passed, 1 failed, 1 skipped. `tests/transport.test.ts:144` expected the raw string `claude` and received the JSON-encoded string `"claude"`, matching the v6 migration guide. No live Pi/provider run or Langfuse ingestion was tested; the Cloud finding is based on the published retirement and the checked-in URLs.
